# Loft Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `/gzloft` (module `loft`): pick points with per-point frames (width/height), then loft a smooth organic surface (outline or filled) along the curve through them — Arceon's Loft tool (spec §2), Phase 1 feature 2.

**Architecture:** Pure engine `modules/loft/engine/LoftPlanner` samples a centripetal Catmull-Rom curve (`shared/shapes/Splines.sample`), interpolates per-station frames, and emits the cells of each elliptical cross-section (outline ring or filled disc), plus optional stack-down columns via a `ColumnGround` lookup. `modules/loft/command/LoftCommand` mirrors `SplineCommand`'s point management (`add`/`here`/`frame`/`remove`/`clear`/`list`/`show` with particles), enforces `Limits.Kind.BLOCKS`, shows `-p` previews through `PreviewService`, applies through `PlayerEdits.async` (`//undo`).

**Tech Stack:** Java 25, Paper 26.2, FAWE 2.16.1, Maven (`mvn -B verify` = CI), JUnit 5 + Mockito.

**Spec:** `docs/arceon-parity-spec.md` §2. Where plan and spec disagree, the spec wins.

## Interfaces (pinned)

`LoftOptions` (engine): `public record LoftOptions(boolean outline, boolean fill, boolean smooth, boolean lowPoly, boolean stackDown, double density, long seed) {}`

`LoftSpec` (engine, implements `ParamSpec`, singleton `INSTANCE`): `id()`="loft"; `patternNames()`=["pattern"]; params: `outline`=(1,0..1,"1 = surface only"), `fill`=(0,0..1,"1 = solid inside"), `smooth`=(1,0..1,"1 = frames blend between points"), `lowpoly`=(0,0..1,"1 = fewer samples and section segments"), `stack-down`=(0,0..1,"1 = stack each column down to the ground"), `density`=(3,1..8,"curve samples per block"). `usage()` = `/gzloft build <pattern> [outline=1] [fill=0] [smooth=1] [lowpoly=0] [stack-down=0] [density=3]`.

`LoftPlanner` (engine, pure; uses `shared.shapes.Splines`):
```java
public final class LoftPlanner {
    public record Station(double x, double y, double z, double width, double height) {}
    public record Cell(int x, int y, int z) {}
    public record Plan(Set<Cell> cells, int blockCount, String problem) {}
    @FunctionalInterface
    public interface ColumnGround { /** Top solid block y at (x,z), or -1. */ int ground(int x, int z); }
    public static Plan plan(List<Station> stations, LoftOptions options, ColumnGround ground) {}
}
```
Algorithm: <2 stations → problem "Add at least two loft points first.". Sample the station centers with `Splines.sample(intPoints, lowPoly ? 1.5 : density)`; track which curve segment each sample belongs to (same steps formula: `max(1, ceil(dist(p1,p2)*density))`); frame at a sample = smooth ? lerp of the segment's endpoint frames by local u : the segment's start station frame. Tangent by neighbour finite difference; basis e1 = normalize(cross(tangent, up)) with up=(0,1,0) unless |tangent.y|>0.9 then (1,0,0); e2 = normalize(cross(tangent, e1)). Section segments = lowPoly ? 8 : clamp(round(pi*(w+h)/2), 12, 48). Outline: cells at round(c + e1*cos(a)*w/2 + e2*sin(a)*h/2) for each angle. Fill: additionally all grid offsets (i,j) with (2i/w)^2+(2j/h)^2 <= 1 mapped through e1/e2. Dedup in a LinkedHashSet. stackDown: per (x,z) column present in the loft, if ground(x,z) >= 0, add cells from ground+1 up to the column's lowest loft cell - 1. `blockCount` = cells.size() (includes stack-down).

`LoftCommand`: `PERMISSION = "gzmnbuildtools.loft"`; per-player `Map<UUID, List<LoftPlanner.Station>>`; `add(player, here, w, h)` (default frame 3x3, looked-at block or standing position, particles), `frame(player, w, h)`, `remove`, `clear`, `list`, `show(seconds)` (END_ROD/FLAME particles like SplineCommand), `build(player, rawArgs)` with `-p` token, `BrushArguments.parse(LoftSpec.INSTANCE, rest)`, pattern via `parsePattern` (same as SplineCommand), count check vs limit, then `PlayerEdits.async`: cells → `PartPlacer.state(x,y,z,0,(char)0)` filtered to world Y range → changes map → preview or apply. Messages: errors for <2 points, bad args, invalid pattern, over limit; success "Lofted %d blocks through %d points. //undo reverts it."

`LoftModule`: id `loft`; help `HelpEntry.of(Category.SHAPES, Material.PAPER, "/gzloft", tr("Loft"), tr("Loft a smooth organic surface through frames you place.")).example("/gzloft build oak_planks").permission(PERMISSION)`; Brigadier literal `gzloft` (alias `loft`) with subcommands `add [w] [h]`, `here [w] [h]`, `frame <w> <h>`, `remove`, `clear`, `list`, `show`, `build <args...>` (greedy, suggestions).

2. Determinism: same seed/options → identical cell set (preview matches apply).
3. Block limit counts stack-down fill, not only the surface.
4. Outline vs fill: fill strictly contains the outline cells.
5. Cells outside world Y range are skipped by the command, not the engine.
